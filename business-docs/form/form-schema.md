# 表单 Schema 规则

## 边界

表单模块维护可被工作流复用的结构定义，并在服务端校验运行时提交值。它不负责流程流转，也不保存独立于使用方的业务提交记录。

## 标识与状态

- **FORM-SCHEMA-001** Schema 标识全局唯一，只允许字母、数字、下划线和点，必须以字母开头，最长 128 个字符。
- **FORM-SCHEMA-002** Schema 名称必填；整体布局只允许单列、双列或三列。
- **FORM-SCHEMA-003** 状态仅允许启用和停用。停用 Schema 不得作为新流程发布时的有效表单来源，但历史实例继续使用自身快照。

## 字段结构

- **FORM-SCHEMA-010** 单个 Schema 最多包含 200 个字段，统计范围包括容器内的子字段。
- **FORM-SCHEMA-011** 字段名遵循与 Schema 标识相同的字符和首字符规则；同一 Schema 内全局唯一，父字段与子字段也不能重名。
- **FORM-SCHEMA-012** 组件类型必须来自后端允许列表，不能通过提交任意前端组件名扩展服务端能力。
- **FORM-SCHEMA-013** 字段配置和校验类型必须来自当前支持集合；自定义脚本或自定义校验器不作为可信服务端规则执行。
- **FORM-SCHEMA-014** 保存时校验整棵字段树，结构、字段名、组件或校验配置任一不合法时整次保存失败。

## 提交校验

- **FORM-SCHEMA-020** 使用方提交的字段必须存在于 Schema；未知字段直接拒绝，不能静默保存。
- **FORM-SCHEMA-021** 服务端依据字段定义校验必填、数据类型及已配置约束，前端校验只用于交互提示，不能替代服务端校验。
- **FORM-SCHEMA-022** 提交值的对象层级必须与 Schema 字段结构匹配；集合字段和标量字段不得互换。

## 工作流联动

- **FORM-LINK-001** 修改 Schema 的字段 JSON、布局或启停状态，会把所有引用该 Schema 的工作流定义退回草稿，要求重新核对并发布。
- **FORM-LINK-002** 只修改名称、分类或备注不改变表单运行结构，不触发工作流定义退回草稿。
- **FORM-LINK-003** 仍被工作流定义引用的 Schema 不允许删除；应先解除全部引用。
- **FORM-LINK-004** 删除采用软删除，并把已删除记录的 Schema 标识替换为内部唯一值，以便原标识可由新 Schema 重新使用；历史流程实例仍以快照为准。

## 接口与权限

模块接口位于 /api/form/schemas，覆盖列表、创建、详情、更新、状态和删除。新增或修改路由时，必须为每个受保护动作配置独占原子权限，并同步前端按钮权限和本文。

## 当前限制

- 表单模块不支持执行任意自定义脚本。
- Schema 本身不提供通用“提交记录”列表；提交数据由工作流等使用方持有。
- 设计器预览用于验证结构和交互，不代表流程发布校验已经通过。
