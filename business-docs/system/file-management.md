# 上传与文件管理规则

## 上传

- **SYS-FILE-001** 单个上传文件大小必须小于 200 MB；超过限制时不创建文件记录。
- **SYS-FILE-002** 服务器使用 UUID 生成存储文件名，保留原文件名作为展示信息，不能信任原文件名直接决定存储路径。
- **SYS-FILE-003** 图片上传会生成缩略图文件；当前缩略图是原文件副本，不代表已经压缩或改变尺寸。
- **SYS-FILE-004** 文件落盘后若数据库元数据写入失败，必须清理已生成的原文件和缩略图，不能留下孤儿文件。

## 查询与边界

- **SYS-FILE-010** 文件列表为分页管理入口，按当前接口筛选和排序返回文件元数据。
- **SYS-FILE-013** 文件元数据列表按 `creator_id` 应用当前角色数据范围；研发需求写入附件引用时也必须确认附件在操作者范围内。
- **SYS-FILE-014** `/uploads/**` 当前由静态目录公开提供，知道 URL 即可访问，不经过文件列表数据权限。需要逐用户授权的医疗、合同或其它敏感文件不得使用该目录，应建设私有下载入口。
- **SYS-FILE-011** 当前没有文件删除 HTTP 入口。不得仅删除数据库记录或磁盘文件的一侧来模拟完整删除。
- **SYS-FILE-012** 上传文件与下载中心导出文件是两类资源，存储目录、权限、保留期和归属规则互不替代。

## 权限现状

- 文件列表受 file:list 原子权限保护。
- 上传路由要求登录，但当前没有单独原子权限。若增加上传权限，必须同步所有调用页面和菜单按钮配置。
- 原子权限、文件元数据数据范围和静态 URL 访问是三个不同边界，不能因列表不可见就认为文件内容已经私有。
