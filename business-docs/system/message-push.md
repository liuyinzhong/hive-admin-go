# 菜单消息推送业务规则

当前消息能力以“某个用户在某个叶子页面菜单下有多少条未读消息”为核心。系统持久化消息记录，通过 SSE 推送完整未读汇总或瞬时任务变化事件。

## 业务规则

### SYS-MSG-001 菜单消息由菜单角标与通知中心共同消费

菜单消息归属于一个用户和一个菜单。菜单角标按菜单聚合展示未读数量；通知中心（顶栏铃铛弹层）逐条展示最近的菜单消息，是菜单消息的逐条消费入口。通知中心只保留最近若干条，不是全量消息归档页，系统也没有独立的归档页面。

### SYS-MSG-002 未读数量按当前用户和菜单聚合

未读汇总只统计当前登录用户 `readAt` 为空的记录，并按菜单 ID 聚合。菜单路径优先使用菜单外链地址，否则使用菜单路径；没有未读消息时返回空数组。

### SYS-MSG-003 进入叶子菜单会整组标记已读

整组已读是进入菜单的唯一已读口径。用户从侧边栏选择、或从通知中心点击消息项跳转进入一个叶子菜单时，该菜单下该用户的全部未读记录一次性写入相同已读时间，并重新推送完整汇总。

后端已读接口只使用登录身份限定用户，不允许调用方指定其他用户。

### SYS-MSG-004 菜单角标向上汇总

叶子菜单显示自身未读数量，目录菜单显示所有子孙菜单未读数量之和。数量超过 99 时展示 `99+`；归零后恢复菜单原有角标配置，而不是永久清空菜单元数据。

### SYS-MSG-005 SSE 先发送全量状态再发送变化

建立连接后，服务端立即发送一次 `unreadSummary`，之后发送未读汇总变化和 `downloadTaskChanged` 事件，并每 30 秒发送心跳。前端连接失败后先重新请求完整未读汇总，等待 2 秒再连接。

实时事件只是刷新提示，不是权威数据：菜单角标使用完整汇总覆盖本地状态；下载中心收到任务变化后重新查询列表。

### SYS-MSG-006 推送只在当前后端进程内广播

订阅关系保存在进程内内存中，每个用户连接使用有限缓冲并在拥堵时保留较新的事件。当前没有 Redis、消息队列或数据库事件总线，多实例之间不会相互转发 SSE 事件。

### SYS-MSG-007 Demo 消息受目标限制

Demo 接口每次可为一个或多个目标用户各创建 1 至 1000 条固定标题和内容的测试消息。目标菜单必须启用、未删除、属于页面类型且没有非按钮子菜单；目标用户必须启用、未删除、不能是系统用户，并且全部处于操作者当前角色数据范围内。重复用户 ID 会去重，任一目标越界时整批失败，整批创建在一个事务中完成。

### SYS-MSG-008 下载终态生成持久化菜单消息

下载任务成功、失败或因服务重启中断时，系统按菜单名称 `downloadCenter` 创建一条归属于任务创建者的菜单消息。创建消息失败不会回滚已经完成的下载任务状态。

### SYS-MSG-009 菜单消息当前没有生命周期清理

当前没有消息删除、过期或定期归档逻辑；已读记录仍保留在 `sys_menu_message`。增加清理规则前必须明确审计需要、保留期和角标统计影响。

### SYS-MSG-010 流程待办与抄送按引擎产物确定性生成菜单消息

流程引擎每生成一条保持待办状态的审批任务，向办理人按菜单名称 `WorkflowTaskList` 创建一条"流程待办通知"；每生成一条抄送记录，向接收人按菜单名称 `WorkflowCopyList` 创建一条"流程抄送通知"。自动通过与或签取消的任务不发；拒绝、撤销、减签不发；转办、加签产生的新待办发；办理人为操作人本人时同样发送。

发送在流程事务提交后执行，复用 `CreateMenuMessageForMenuName`，单条失败仅记录日志，不回滚流程流转。菜单消息已读（进入绑定菜单整组已读）不代表审批任务被处理或抄送记录已读，两组状态相互独立（见 [ADR 0003](../docs/adr/0003-workflow-notice-via-menu-message.md)）。

### SYS-MSG-011 通知中心提供最近消息列表与三种已读动作

列表接口返回当前用户最近 100 条消息（含已读，按创建时间倒序），每条携带归属菜单名称与跳转路径；跳转路径与未读汇总一致，外链地址优先，否则使用菜单路径。来源菜单已删除时名称与路径为空，该消息不可跳转，只能通过逐条已读处理。

通知中心不删除消息，只提供三种已读动作：点击消息项按整组已读口径处理并跳转归属菜单；消息项上的标为已读按钮做逐条已读，是系统内唯一的单条已读路径，不跳转、不影响同菜单其它消息；头部全部已读按钮做全量已读，把当前用户全部未读一次性置为已读。列表在打开弹层时拉取，打开期间不实时刷新，实时性由未读汇总推送承担（见 [ADR 0004](../docs/adr/0004-notification-center-component.md)）。

## 接口与权限

| 接口 | 用途 | 权限边界 |
|---|---|---|
| `GET /api/system/messages` | 通知中心最近消息列表（含已读，最多 100 条） | 登录即可，只返回本人 |
| `GET /api/system/messages/unreadSummary` | 当前用户未读汇总 | 登录即可，只返回本人 |
| `GET /api/system/messages/stream` | 当前用户 SSE | 登录即可，只订阅本人 |
| `POST /api/system/messages/read` | 当前用户某菜单全部已读 | 登录即可，只更新本人 |
| `PUT /api/system/messages/{messageId}/read` | 当前用户逐条已读 | 登录即可，只更新本人 |
| `PUT /api/system/messages/readAll` | 当前用户全部已读 | 登录即可，只更新本人 |
| `POST /api/system/messages/demo` | 批量创建测试消息 | `system:messageDemo:create`，目标用户受数据范围约束 |

`CreateMenuMessageForMenuName` 是后端内部能力，不是外部 HTTP 接口。
