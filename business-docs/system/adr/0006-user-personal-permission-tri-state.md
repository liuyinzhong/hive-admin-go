# 用户个人权限：三元合并模型（角色 + 额外授权 − 禁止）

权限此前完全由角色承载：用户要获得或失去一个菜单，只能新建或修改角色，而角色变更影响全部持有者。决定引入用户维度的个人权限，并采用三元合并模型：用户生效权限 = 全部有效角色授权 ∪ 个人额外授权 − 个人禁止，禁止在合并时绝对优先；个人权限只作用于菜单与按钮（功能权限），数据范围仍完全由角色决定。

明确拒绝两个更简单的备选：其一，纯附加并集（只加不减）实现最省，但无法对个别人屏蔽危险按钮，收回权限仍要动角色，痛点只解决一半；其二，覆盖式整体替换（个人权限完全脱离角色），会让用户权限与角色脱钩，授权审计需要在用户和角色两处拼图，且数据范围仍依赖角色，模型分裂。三元模型用一个禁止集合换回"对个别人收权"的能力，合并逻辑保持纯函数（角色集合在合并时只读）。

数据范围不引入个人级是有意为之：数据范围驱动记录可见性，个人级数据范围会让权限审计和数据边界难以推理，且用户的部门归属本身来自角色和部门关联。已知边界（有意识接受）：禁止一个角色里不存在的菜单是冗余项，保存时不校验、合并时无效果；额外授权一个用户角色已有的菜单同样冗余但无害。个人权限的授予与禁止都要求操作者自己持有对应菜单（全部数据范围操作者豁免），镜像角色分配的防提升约束。
