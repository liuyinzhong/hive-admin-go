# 登录防爆破：失败触发滑块，不硬锁账号

登录此前没有任何防爆破手段（无验证码服务端校验、无失败计数、无锁定、无限流），且存量用户口令统一。决定采用"失败触发滑块"组合：直接统计 `sys_login_log` 滚动窗口内某用户名的失败次数（零新表，索引现成），达到阈值后登录必须携带有效的一次性滑块挑战票据；票据由公开接口签发、登录时一次性消费，签发接口按 IP 限流，阻止脚本无限领票。阈值以下不校验，正常用户无感。

明确拒绝账号硬锁定：任何人都能故意输错把他人账号锁死，锁定的 DoS 面大于其防护收益；脚本绕过滑块的路径由"票据一次性 + 签发限流 + 失败计数"三层共同提高成本，而非依赖滑块本身不可破。挑战票据存进程内存（丢失仅要求用户重滑一次，无害），令牌撤销黑名单存数据库（撤销跨重启必须持久），两者存储介质按丢失后果区分。

后续复核确认的已知边界（2026-09-15，有意识接受）：挑战票据可被脚本自助领取且未绑定签发 IP（可跨 IP 集中消费），对认真攻击者的实际约束有限；账号指数退避与 IP 失败限流等与票据解耦的节奏管控经评估后明确不做——本项目为个人项目，防护定位是抬高随手攻击成本，不追求对抗定向爆破。
