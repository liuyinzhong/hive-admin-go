# 系统用户口令以 bcrypt 哈希存储，不做明文兼容

`sys_user.password` 此前以明文存储与比对（登录等值比较、创建用户直写入库）。决定统一改为 bcrypt 哈希：复用已在依赖树中的 `golang.org/x/crypto`，哈希串自含盐与成本因子，不新增独立盐字段。曾考虑 argon2id（OWASP 现代首选），但 `x/crypto` 仅提供原语，需手写 PHC 编解码或新增第三方依赖，与项目"最简不冗余"原则冲突，故弃。

切换成本高：算法一旦落地，全部存量口令哈希只能通过重置再生，无法机密还原。因此同时决定：代码不做明文/哈希双格式兼容，登录一律走 bcrypt 比对；存量明文数据按"清空重建"处置，`hive.sql` 仅视为数据库备份文件不做修改，也不编写明文转哈希的过渡迁移。

为将来扩展 MFA，不预留任何字段或表：MFA 届时以新增列、新增接口和登录二步流程的纯增量方式接入，与口令哈希无结构耦合。
