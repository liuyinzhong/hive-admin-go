# 登录与访问控制规则

## 登录和当前用户

- **SYS-ACL-001** 登录成功后使用 Bearer Token 访问受认证接口；无效、过期或缺失 Token 不能进入业务路由。
- **SYS-ACL-002** 已停用用户不能正常登录或继续作为有效业务办理人使用。
- **SYS-ACL-003** 当前用户资料包含其有效角色等授权上下文；退出使客户端结束当前会话，服务端记录登录审计。
- **SYS-ACL-004** 系统内置超级用户取得全部启用菜单和权限码；普通用户的生效权限按三元合并计算：全部有效角色关联的启用菜单 ∪ 个人额外授权 − 个人禁止（SYS-ACL-019），动态菜单与权限码集合同源计算。
- **SYS-ACL-005** 当前用户可通过 `PUT /api/auth/profile` 维护自己的头像、邮箱和签名图片：字段为 null 表示不修改、空字符串表示清空；邮箱非空时校验格式且不超过 128 字符，头像和签名图片 URL 不超过 512 字符。该接口只处理当前 Token 对应用户，不经过角色数据范围，也不开放登录名、真实姓名、手机号等由用户管理维护的字段。个人签名只是资料，不构成审批证据；审批证据以工作流签名快照为准（见 workflow 运行规则 WF-RUN-023）。

## 用户

- **SYS-ACL-010** 用户名全局唯一。普通用户管理列表排除系统内置用户，防止其被常规批量操作影响。
- **SYS-ACL-011** 用户的角色和部门按提交集合完整替换；未提交在新集合中的旧关联会被移除。
- **SYS-ACL-012** 直属领导为可选有效用户，不能选择自己。领导关系不等同于角色授权。
- **SYS-ACL-013** “全部用户”选项只返回启用、未删除且非系统内置用户，供人员选择使用。
- **SYS-ACL-014** 用户状态只允许启用或停用。软删除用户时同时清理其角色、部门关联和个人权限；当前用户和系统内置用户不能通过普通删除入口删除。
- **SYS-ACL-015** 用户列表、全量选项、详情、修改、启停和删除受当前角色数据范围限制。用户属于多个部门时，查询以任一可见部门为准；写操作要求其全部启用部门都在操作者范围内。
- **SYS-ACL-016** 非全部数据范围操作者只能把用户放入自己可管理的启用部门，只能分配自己持有的有效角色，且目标角色展开后的部门范围不能超过操作者范围。
- **SYS-ACL-017** 越界的直属领导和部门关联不返回给受限操作者；保存时直属领导也必须是当前可见的启用普通用户。
- **SYS-ACL-018** 用户权限明细：`GET /api/system/users/{userId}/permissions` 一次返回目标用户全部关联角色及各自菜单授权明细（权限码 `system:user:permission`，角色数据范围，与用户详情同边界）。明细按配置事实返回，与登录后动态菜单的生效口径（SYS-ACL-004）是两个边界：停用角色与停用菜单照常返回并携带状态；明细按菜单树层级嵌套（目录→页面→按钮），目录作为层级节点保留其下被授权的后代，未被授权且无授权后代的目录不出现；多角色重复授权的权限在各角色分组内分别出现，不去重；已删除角色或菜单不出现。响应同时携带个人权限分组（额外授权树与禁止树及各自数量）。用户分页列表每行携带权限摘要计数：`rolePermissionCount`（各未删除角色授权节点数之和，多角色重复授权不去重，与明细各角色分组计数一致）、`grantCount` 与 `denyCount`（个人额外授权与禁止节点数）；角色数由 `roleIds` 派生，摘要同样按配置事实口径统计。
- **SYS-ACL-019** 用户个人权限：直接作用于单个用户的菜单授权调整，由个人额外授权和个人禁止两个集合组成，维护入口聚合在用户编辑抽屉（见 [ADR 0007](./adr/0007-user-edit-aggregates-personal-permissions.md)）：`POST /api/system/users` 与 `PUT /api/system/users/{userId}` 接受可选的 `grantMenuIds`/`denyMenuIds` 字段（nil 表示不修改，非 nil 按完整集合替换，携带时在服务层校验操作者持有权限码 `system:user:personalPermission`，因创建/更新路由只能硬编码挂各自权限码）；`GET /api/system/users/{userId}` 响应聚合两个集合，供编辑抽屉一次加载；可勾选的启用菜单树由 `GET /api/system/users/personalPermissionMenuTree`（权限码 `system:user:personalPermission`）提供，是新建与编辑抽屉的唯一树来源，维护个人权限不要求菜单管理列表权限。个人权限调整的角色数据范围边界与用户详情一致。生效合并为：有效角色授权 ∪ 额外授权 − 禁止，禁止绝对优先，仅启用菜单进入生效口径；系统内置超级用户不受个人禁止影响，也不能被配置个人权限。个人权限只影响功能权限（菜单与按钮），不改变数据范围（数据范围仍完全由角色决定）。授予与禁止都要求菜单有效、启用且在操作者生效权限内，全部数据范围操作者豁免（防提升，镜像 SYS-ACL-016）；同一菜单不允许同时额外授权和禁止。禁止角色中不存在的菜单是冗余项，保存不校验、合并无效果。删除用户或菜单时个人权限随关联一并清理（SYS-ACL-014、SYS-ACL-026）。个人权限调整对目标用户已签发会话即时生效（动态菜单与权限码每次请求实时计算）。语义模型见 [ADR 0006](./adr/0006-user-personal-permission-tri-state.md)。

## 密码与会话

- **SYS-ACL-040** 密码以 bcrypt 哈希存储，哈希自含盐与成本因子，不存明文、不设独立盐字段；任何列表、详情、全量选项、个人资料接口的响应都不包含密码字段，通用更新用户接口不接受密码参数，密码写入只能通过创建用户或下述两个专用入口。
- **SYS-ACL-041** 密码强度统一策略：不少于 8 个字符且不超过 72 字节，至少包含小写字母、大写字母、数字、特殊字符四类中的两类；创建用户、修改密码、重置密码三个入口执行同一策略，前端表单校验与后端校验保持一致。
- **SYS-ACL-042** 密码变更只有两个入口：本人修改（`PUT /api/auth/password`，验证旧密码，新旧不能相同，当前用户归属）与管理员重置（`PUT /api/system/users/{userId}/password`，需要 `system:user:resetPassword` 权限码，角色数据范围，写前在同一查询中校验目标用户可见，系统内置用户不可重置）。
- **SYS-ACL-043** 密码版本号：口令修改或重置成功后 `pwd_version` 递增；登录签发的 Token 携带签发时刻的版本号，认证中间件对每个请求比对版本，不一致返回 401，该用户全部旧世代凭证立即失效。同一查询顺带校验停用与已删除状态，被禁用用户的既有 Token 同样立即失效。
- **SYS-ACL-044** 密码变更成功后向目标用户推送 `forceLogout` 实时事件，其全部在线页签立即清理会话返回登录页（见 [菜单消息推送业务规则](./message-push.md) SYS-MSG-012）；本人修改密码后同样被踢出，需用新密码重新登录。管理员重置还会向目标用户创建一条归属用户管理菜单的站内消息，消息发送失败不影响重置结果。
- **SYS-ACL-045** 登录有效期以小时为单位取系统参数 `SYS_LOGIN_VALIDITY_PERIOD`，参数缺失、类型不符或越界时回退默认 24，合法范围 1～8760；参数仅在登录签发时消费，修改参数不追溯已签发凭证。
- **SYS-ACL-046** 登录防爆破采用失败触发滑块：某用户名在 15 分钟窗口内自最近一次成功登录以来的连续失败次数（统计自登录日志，见 SYS-AUD-002；成功登录即清零计数，登出后重新登录不延续触发）达到系统参数 `SYS_LOGIN_FAILURE_CAPTCHA_THRESHOLD`（默认 3，范围 1～100，缺失或非法回退默认值）后，登录请求必须携带有效的滑块挑战；阈值以下忽略挑战参数。需要滑块验证时登录接口以 HTTP 428 与普通密码错误（400）区分，登录页默认不展示滑块，收到 428 后才展示并领取票据。滑块挑战由公开接口签发、随登录一次性消费，有效期 5 分钟；同一 IP 每分钟最多签发 10 次。不校验拖动耗时：耗时可以谎报，校验无防护价值且会误伤快速拖动的用户。挑战与限流为进程内状态，重启丢失仅要求重新滑动，不硬锁账号（见 [ADR 0005](adr/0005-login-bruteforce-captcha-gating.md)）。
- **SYS-ACL-047** 登出即令牌撤销：登录凭证签发时携带唯一标识（jti），登出将其写入黑名单并保留至原过期时刻，认证中间件按 jti 拦截；撤销只失效当前凭证，同一用户其它会话不受影响。过期黑名单行由审计日志清理任务顺带删除。
- **SYS-ACL-048** JWT 签名密钥仅来自 config.json，长度不足 32 字节时服务拒绝启动；接口文档同步 Apifox 的凭证与地址同样来自 config.json 的 apifox 配置，token 或 projectUrl 为空时启动跳过同步，不向外部发送数据。

## 角色、部门与菜单

- **SYS-ACL-020** 角色名称全局唯一；角色权限由角色与菜单节点的关联集合表达，更新时按完整集合替换。角色分页列表（`GET /api/system/roles`）与全量接口（`GET /api/system/roles/all`）均携带 `permissionsCount`：角色当前配置的菜单授权节点总数（配置事实口径，不筛菜单启停，与用户权限明细各角色分组计数同口径），供角色列表权限数量列与用户编辑抽屉角色选项展示使用。
- **SYS-ACL-021** 删除角色采用软删除并清理角色菜单关联。当前实现未阻止删除仍被用户引用的角色，修改此行为前必须评估存量用户授权影响。
- **SYS-ACL-022** 部门是树结构，名称当前按全局唯一校验。部门不能以自身或后代为父节点。
- **SYS-ACL-023** 有子部门或仍有关联用户的部门不能删除。
- **SYS-ACL-024** 菜单节点类型包括目录、页面、内嵌页、外部链接和按钮；不同类型只允许填写其适用字段。
- **SYS-ACL-025** 非按钮菜单的名称和路径按当前规则保持唯一；按钮节点以原子权限码表达动作，不承担页面路由。
- **SYS-ACL-026** 删除菜单前必须没有子菜单；删除时同时移除角色和用户个人权限对该菜单的授权关系。
- **SYS-ACL-028** 菜单受众：`GET /api/system/menus/{menuId}/roles` 返回收录该菜单的全部未删除角色（含停用并携带状态），`GET /api/system/menus/{menuId}/users?grantType=grant|deny` 分页返回被直接额外授权或禁止该菜单的普通用户；两者均为只读配置视图（权限码复用 `system:menu:detail`），全局授权配置口径，不做记录级数据范围过滤。
- **SYS-ACL-027** 角色还维护数据范围。`customDepartment` 必须选择至少一个启用部门，其它范围会清空自定义部门集合；创建、更新、启停和删除角色要求操作者拥有全部数据范围，避免受限管理员扩大自身或他人范围。

## 接口权限

- **SYS-ACL-030** 登录认证和接口权限是两层校验：已登录不代表可以调用所有业务接口。
- **SYS-ACL-031** 每条受保护路由必须硬编码一个独占原子权限码；不能根据请求参数或前端传值动态决定所需权限。
- **SYS-ACL-032** 前端按钮隐藏只改善交互，后端权限中间件仍是动作授权边界。
- **SYS-ACL-033** 接口权限与业务归属同时生效。例如医生工作台还要验证当前用户绑定医生及排班归属。
- **SYS-ACL-034** 接口权限通过后，记录级访问继续按 [数据权限规则与接口分类](./data-permission.md) 执行。前端传入的部门、创建人或数据范围值不能替代服务端解析结果。

## 当前风险

- 角色删除当前没有阻止仍被用户引用的情形，应在改变规则前先盘点存量关联。
- 新增路由必须同步菜单按钮数据；仅新增前端按钮或仅注册后端权限都会造成授权不完整。
- 当前认证 Router 提供账号密码登录、当前资料读取与更新（头像、邮箱）、修改密码、动态菜单、权限码和退出；管理员重置密码挂在用户管理路由下。仍没有注册、短信验证码登录、二维码登录、找回密码或 MFA。前端同名页面不能被视为已实现业务能力。
- 防爆破失败触发阈值参数 `SYS_LOGIN_FAILURE_CAPTCHA_THRESHOLD` 未配置时默认 3 次，需要按环境在参数管理中显式配置。
- 防爆破与滑块挑战均为单实例进程内状态，多实例部署时失败计数仍以登录日志为准跨实例生效，但挑战票据与签发限流不互通。
- 滑块挑战的防护定位是抬高脚本直调成本（票据一次性 + 签发限流 + 失败计数三层组合），不承诺滑块交互本身不可被自动化工具模拟。
- 挑战票据未绑定签发 IP，可跨 IP 集中消费，签发限流可被横向绕过；账号退避与 IP 失败限流等更强的节奏管控经评估明确不做（见 [ADR 0005](adr/0005-login-bruteforce-captcha-gating.md)）。
