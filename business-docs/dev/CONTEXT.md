# 开发管理领域词汇

用于统一项目规划、研发工作项和统计中的核心语言。状态取值和操作约束写在模块规则文档中。

**项目**：研发工作的最高归属范围。
_Avoid_: 系统模块、业务领域

**项目用户**：归属于某一项目的系统用户，通过 `dev_project_user` 关联表管理，仅表示人员归属，不携带负责状态。需求参与人、缺陷修复人和任务执行人的候选范围均来自项目用户。
_Avoid_: 项目成员、项目角色、项目成员角色

**项目模块**：项目内用于拆分功能范围的工作分类。
_Avoid_: Go 包、前端路由模块

**版本**：项目在一段时间内计划和发布工作成果的载体。
_Avoid_: 数据行版本、接口版本

**需求**：描述待评审和待交付业务价值的研发工作项。
_Avoid_: 任务、缺陷

**需求参与人**：关联到某条需求的用户，通过独立关联表 `dev_story_user` 管理；数据来源为需求流转：每次流转由操作人指定目标状态负责人写入一行（`story_status` 为 STORY_STATUS 字典值），同一需求同一状态仅保留最新负责人。"参与人"即历次各状态的负责人集合。
_Avoid_: 项目用户、需求负责人、user_ids 逗号拼接

**任务**：描述需要执行、分派和登记工时的具体研发工作项。
_Avoid_: 下载任务、排班自动任务

**缺陷**：描述需要确认和修复的软件问题。
_Avoid_: 需求、系统异常日志

**工作项流转**：通过明确动作修改版本、需求、任务或缺陷业务状态的过程。
_Avoid_: 通用字段编辑

**需求批量流转**：一次动作将多条需求流转到同一目标状态，并指定同一位状态负责人。
_Avoid_: 批量推进、逐条流转

**需求批量创建**：一次动作在一个事务内创建多条需求，任一条失败整批回滚；创建后与单条创建一致自动发起流程。
_Avoid_: 批量新增（接口语义）、循环调用单条创建

**缺陷确认**：对待确认缺陷作接受或拒绝判断的独立动作。
_Avoid_: 缺陷状态流转

**变更记录**：关联某个研发对象、记录创建、修改、删除、流转或确认行为的时间线记录。
_Avoid_: 系统操作日志、Git 提交

**开发统计**：按日期、年份或工作台口径汇总研发工作项的数据投影。
_Avoid_: 业务主数据、审计记录
