# 挂号主流程规则

## 状态

| 值 | 状态 | 说明 |
|---:|---|---|
| 0 | 待支付 | 已占用号源，等待支付 |
| 10 | 已支付 | 可以在适当时间签到或发起退款 |
| 30 | 已签到 | 已进入候诊队列 |
| 50 | 已完成 | 正式接诊流程完成 |
| 60 | 已取消 | 待支付挂号被取消 |
| 70 | 已爽约 | 时段结束仍未签到 |
| 80 | 退款申请中 | 已发起退款请求 |
| 90 | 退款处理中 | 外部或人工退款正在处理 |
| 100 | 已退款 | 退款完成并释放号源 |

允许的挂号管理流转为：待支付到已支付或已取消；已支付到已签到、已爽约或退款申请中；退款申请中到退款处理中；退款处理中到已退款。已签到到已完成只由正式医生接诊流程触发。

## 创建与号源

- **MED-REG-001** 创建挂号要求患者启用，实际排班已发布、日期有效且目标号源档位仍可用。
- **MED-REG-002** 创建时固化医生、科室、挂号类型和费用等展示快照，生成 REG 前缀业务单号。
- **MED-REG-003** 同一患者不能对同一实际排班重复持有仍有效的挂号；已取消或已退款记录不阻止重新挂号。
- **MED-REG-004** 创建和占用号源在同一事务内完成，并通过锁或条件更新避免超额预约。
- **MED-REG-005** 每次状态动作写入挂号生命周期日志，不能只改主表而丢失操作轨迹。
- **MED-REG-006** 挂号列表、详情、支付、取消、签到、爽约和退款动作按挂号单 `creator_id` 应用当前角色数据范围。创建挂号前，患者和实际排班都必须在操作者范围内；知道患者、号源或挂号 ID 不能绕过该校验。

## 支付、取消和退款

- **MED-REG-010** 待支付挂号支付成功后进入已支付；支付信息以当前接口字段和挂号费用快照为准。
- **MED-REG-011** 只有待支付挂号可取消，取消原因必填，并在同一事务内释放已占号源。
- **MED-REG-012** 只有已支付且尚未签到的挂号可以发起全额退款，退款原因必填；当前不支持部分退款。
- **MED-REG-013** 退款完成时进入已退款并释放号源。退款申请中或处理中不提前释放，避免外部退款失败后号源已被再次占用。

## 签到、爽约和完成

- **MED-REG-020** 已支付挂号签到后进入已签到，并在同一事务内创建唯一候诊记录和签到序号；详细规则见 [候诊队列规则](./visit-queue.md)。
- **MED-REG-021** 只有号源时段已经结束、仍处于已支付且未签到的挂号可以标记爽约；爽约不释放已消耗号源。
- **MED-REG-022** 挂号管理没有独立完成动作。只有医生工作台完成病历校验和接诊事务后，挂号由已签到进入已完成。
- **MED-REG-023** 过号是候诊状态，不改变挂号为爽约；二者不能混用。

## 终态和边界

已完成、已取消、已爽约和已退款为当前终态。挂号模块不替代支付订单、门诊病历或处方；状态变化必须同步相关号源、候诊和接诊副作用。
