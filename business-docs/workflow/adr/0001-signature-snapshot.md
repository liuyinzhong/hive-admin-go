# ADR-0001：审批签署采用签名快照复制

- 状态：已采用
- 日期：2026-09-15

## 背景

系统用户在个人中心维护个人签名（图片 URL 资料），审批流程需要把"谁、在什么时候、用什么签名签署"作为不可变的审批证据随流程记录保存。个人签名可随时修改或清空，上传文件也可能被删除；若审批记录只引用个人签名的当前 URL，历史单据展示的会是签署人"现在"的签名，甚至图片失效，无法满足证据要求。

## 决定

签署动作（同意、拒绝、退回）发生时，由流程引擎在同一操作内把签署人当前个人签名复制为流程私有快照文件（`static/uploads/workflow-sign/{实例ID}/{任务ID}.{扩展名}`），并把快照 URL 写入该次流程记录（`wf_process_record.signature`）：

1. 审批历史与后续展示一律读取流程记录中的快照，不回读 `sys_user.signature`。
2. 快照不登记 `sys_file`，不出现在文件管理中，不受文件删除与孤儿清理影响，无保留期与清理任务。
3. 办理人未设置个人签名时签署不阻塞，记录签名为空；源文件缺失或复制失败时该次签署操作失败回滚，不允许"签了但没证据"。
4. 转办、加签、减签、撤销与自动通过不属于签署，不产生快照。

## 取舍

- 复制文件使历史证据与个人资料、文件管理彻底解耦；代价是少量重复存储（签名图仅数 KB）和签署时一次磁盘复制。
- 只在 `wf_process_record` 单列落库而不双写任务表：任务完成后必然产生记录，审批历史是唯一展示出口，双写没有第二个读取方。
- 不采用 base64 直存记录：数十 KB 字符串进入记录表会拖累审批历史查询，无可验证性收益。
- 未设置签名不阻塞签署：强制签名需要节点级配置（定义域改动），留作后续独立需求。

## 后果

流程记录新增 `signature` 列需要迁移；打印模板将来需要展示签署签名时，必须取审批记录的快照字段，禁止运行时拼用户资料地址；个人签名的语义从此明确为"资料来源"而非"审批证据"。
