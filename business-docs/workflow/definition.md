# 流程定义规则

## 生命周期

- **WF-DEF-001** 流程定义标识由后端通过公共编码流水 `base_code_sequence` 的 `WORKFLOW_DEFINITION` 域自动生成，格式为 `WF` + 6 位补零流水号（如 `WF000001`），全局唯一且递增，不接受前端传入；创建后只读回显，不可修改。新建定义版本为 0、状态为草稿。
- **WF-DEF-002** 定义状态为草稿、已发布或已停用。只有已发布定义允许发起新实例。
- **WF-DEF-003** 修改流程图、画布配置或绑定表单的运行结构后，定义退回草稿；必须重新发布。
- **WF-DEF-004** 发布成功时版本递增。已有实例保存定义、流程和表单快照，不跟随后续修改。
- **WF-DEF-005** 删除采用软删除；历史实例继续使用自身快照，不因定义删除而丢失运行记录。

## 发布校验

- **WF-DEF-010** 流程图必须且只能有一个开始节点，并至少有一个结束节点。
- **WF-DEF-011** 节点类型只允许开始、审批、条件、抄送和结束；普通节点必须有且只能有一条有效出口，结束节点不能有出口。
- **WF-DEF-012** 审批节点办理人来源只允许用户、直属领导或角色，审批方式只允许或签或会签。
- **WF-DEF-013** 条件节点至少两条出口，每条优先级为唯一正整数，并且必须且只能有一条默认出口。
- **WF-DEF-014** 条件表达式使用受支持的结构化规则和运算符，不能提交任意执行脚本。
- **WF-DEF-015** 绑定表单时，发布要求 Schema 处于启用状态且存在可提交值字段；无有效表单结构时不得发布。
- **WF-DEF-016** 节点字段权限只允许隐藏、只读和可编辑，且只能引用绑定 Schema 中的字段。字段权限可配置于发起节点和审批节点：发起节点未配置字段默认可编辑，审批节点默认只读。
- **WF-DEF-017** 结束节点开启结束后动作（创建需求）时，流程定义不能声明业务归属类型：业务归属类型表示流程服务于已有业务对象（状态同步事件回写状态、需求自动发起流程按其匹配），与结束后创建新需求并存会导致自动发起误匹配和状态回写错乱。
- **WF-DEF-018** 开启结束后动作（创建需求）的流程定义必须绑定表单，且表单包含 `story_title` 字段（需求表非空字段）；表单未提供该字段时运行期落地必然失败，发布阶段前置拦截。

## 结束后动作

- **WF-DEF-030** 结束后动作配置在流程设计器的结束节点属性上，随画布 JSON 保存（属性键 `createStoryOnFinish`），不修改流程定义表结构；第一版仅支持"创建需求"一种动作。
- **WF-DEF-031** 结束后动作与状态同步事件是并列且互斥方向的两类节点配置：状态同步事件配置在审批节点上，把流程流转回写到**已有**业务对象的状态；结束后动作配置在结束节点上，在流程通过后**创建**新业务对象。
- **WF-DEF-032** 修改结束后动作属于画布配置变更，定义退回草稿并需重新发布；已有实例保存画布快照，按发起时的配置决定是否落地。

## 与表单联动

- **WF-DEF-020** 表单 Schema 的字段 JSON、布局或状态发生结构性变化时，引用定义被退回草稿；重新发布前必须核对条件和字段权限。
- **WF-DEF-021** 定义发布只验证当时结构；运行实例以发布快照为准，不能读取最新草稿替换实例结构。

## 数据边界

流程定义、画布和表单绑定是全局配置，不按定义创建人应用角色部门数据范围；各动作仍需独立原子权限。流程实例、任务和抄送不继承定义创建人的范围，而按运行时参与者规则控制。
