# Spec: 变更记录增加字段级明细（change-history-field-diff）

日期: 2026-09-18
状态: 已认可（对话确认）
ADR: business-docs/dev/adr/0001-change-history-field-diff.md

## Problem Statement

开发管理中需求、任务、缺陷的变更记录此前只记录行为类型和业务类型：整体修改、局部字段修改的正文为空，无法看出"改了哪个字段、从什么值改成什么值"；流转的状态变化、工作流自动化的字段更新只拼在富文本正文里，非结构化，前端无法稳定展示。

## Solution

在变更记录上增加结构化字段级明细（变更明细）：系统在修改、流转、确认、自动化修改字段的业务事务内自动计算变化字段的旧值→新值，随变更记录一并保存；前端时间线在原有行为标签、正文之上渲染明细列表（`字段名：旧值 → 新值`）。存量记录无明细时按原样式降级展示。

## User Stories

1. 作为项目成员，我想在需求详情的变更记录里看到每次整体修改具体改动了哪些字段（如 状态：待评审→开发中），以便不用对比表单就了解变更内容。
2. 作为项目成员，我想在任务变更记录里看到局部修改（负责人、类型、起止时间）的旧值和新值，以便追踪排期调整。
3. 作为项目成员，我想在缺陷变更记录里看到确认动作的结构化结果（确认状态、缺陷状态的前后值），以便复核确认结论。
4. 作为项目成员，我想看到流转记录的结构化状态变化（从状态A→状态B），而不只依赖手填说明。
5. 作为项目成员，我想看到工作流自动化引起的状态变化也以明细形式记录（含来源流程信息仍在正文），以便区分人工与自动变更。
6. 作为项目成员，我想看到描述（富文本）修改时记录"描述已更新"而非内容级 diff，避免时间线被长文本淹没。
7. 作为项目成员，我想看到附件修改时记录新增/移除的文件名，以便追踪附件变化。
8. 作为项目成员，查看历史旧记录（无明细）时展示不报错、样式不劣化。
9. 作为英文界面用户，我接受字段标签与引用值按写入时刻的中文固化展示（与现有正文行为一致）。
10. 作为评论者，我继续用现有评论入口发表富文本评论，评论记录不产生字段明细。
11. 作为管理员，我不需要做存量数据迁移即可上线该功能。
12. 作为开发者，字典值（状态、类型、级别等）由前端字典翻译展示，字典改名后历史时间线自动跟进。

## Implementation Decisions

1. **存储**：`dev_change_history` 新增 `change_items`（text）列，存 JSON 数组 `[{fieldKey, fieldLabel, dictType, oldValue, newValue}]`。新增迁移 SQL（仅创建脚本，由用户手动执行），含回滚脚本。
2. **值翻译**：字典值存原始值 + `dictType`，前端用现有字典工具翻译；引用值（人名、版本名、模块名、需求标题、文件名）与 `fieldLabel` 由后端写入时翻译固化。
3. **覆盖写入点**（均先读旧值、事务内 diff、只记真正变化的字段）：
   - 需求：整体修改、局部修改（storyType/storyLevel/source）、流转、批量流转；
   - 任务：整体修改、局部修改（userId/taskType/startDate/endDate）、流转；
   - 缺陷：整体修改、局部修改（fixUserId/bugLevel/bugEnv/bugType/bugSource）、流转、缺陷确认；
   - 工作流自动化修改字段值：明细 + 正文保留来源流程描述。
4. **特殊字段**：富文本描述记一条"描述已更新"；`file_ids` 比对后记附件增删文件名；无变化的字段不出现在明细中；空值显示为"空"。
5. **接口**：`GET /dev/changeHistory` 响应新增 `changeItems` 数组；`POST /dev/changeHistory`（评论）不变。
6. **前端**：时间线项在行为标签下、正文之上渲染明细列表（`字段名：旧值 → 新值`），字典值走 `getLocalDictText`，无明细降级为现状。
7. **领域注册表**：后端按业务类型维护字段目录（fieldKey→标签→dictType→取值器），复用现有自动化动作的业务类型定义思路。
8. **Swagger**：变更记录查询接口注释与响应 DTO 同步更新。

## Testing Decisions

当前阶段以编译、`go vet`、`go build` 验证为主（项目约定不默认新增 `_test.go`）；前端以类型检查为主。人工验证路径：整体修改一条任务 → 查看时间线明细字段与旧新值正确；评论、创建记录不受影响。

## Out of Scope

- 存量变更记录的补录与迁移；
- 富文本内容级 diff；
- 变更记录的修改/删除接口；
- 按字段过滤/聚合变更记录的查询；
- 版本（businessType=30）写入点的明细增强（保持现状，如需要另行提出）。

## Further Notes

- 迁移 SQL 仅创建脚本，不自动执行；数据库结构变更由用户手动执行。
- 评论接口（POST /dev/changeHistory）是三个详情页的评论入口（changeBehavior=30），保持富文本正文，不接入明细。
